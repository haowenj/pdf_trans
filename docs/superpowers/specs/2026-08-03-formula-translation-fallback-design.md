# 公式占位符失败后的正文翻译降级设计

## 背景

当前正文翻译默认以完整段落调用模型，并使用公式占位符保护公式。模型返回后如果占位符缺失、重复、篡改或出现未知占位符，系统会先按 `max_retries` 做一次整段重试，仍失败后才尝试按完整英文句子拆分。

测试环境任务 `b020348a-1915-4fc8-9d62-2c13ca39e487` 显示，7 个最终失败正文均进入了拆分降级，但由于段落没有超过 600 字符或 4 个公式阈值，拆分器实际只生成了一个 chunk，最终报“无法按完整句子拆分”。另有 page 7 的正文出现第一片段回退英文、后续片段翻译成功的混合语言结果。

## 目标

在不改变绝大多数正文正常整段翻译流程的前提下：

1. 所有正文调用都使用明确的公式保护和翻译边界基础提示词。
2. 仅在整段公式占位符校验失败且整段重试仍失败后，按完整英文句子进行更细的降级拆分。
3. 对已经进入降级路径的片段追加强化公式保护提示词。
4. 多句短段落即使没有超过字符数或公式数阈值，也必须能够实际拆分；单句段落不硬切。
5. 片段失败时仅回退该片段，成功片段继续保留中文。

## 非目标

- 不把所有正常正文改成逐句翻译。
- 不改变正常整段翻译的请求次数、输入结构和结果恢复流程。
- 不修改表格单元格批量翻译流程。
- 不引入全量语义质量评估或依赖外部语言检测器。
- 不在无法找到完整句子边界时硬切字符或切断公式。

## 设计

### 基础提示词

替换现有基础 system prompt 中模糊的“保留 LaTeX/占位符”描述，明确分为不可变内容和翻译边界：

- 公式占位符是不可翻译的原子字符串，必须逐字保留，每个 ID 只能出现一次；
- 不得删除、复制、拆开、插入空格、插入文字或篡改占位符；
- 占位符可随中文语序移动，不要求保持原文顺序；
- 设备编号、控制回路编号、产品型号、引用编号、数字、单位、化学式和必要专有名词可保留；
- 除不可变内容外，所有英文说明、谓语、修饰语和连接词都必须翻译；
- 技术术语按化工语境翻译，不因邻近公式或设备编号而原样保留整句；
- 正文只返回译文，结构化请求只返回符合结构的结果。

该基础提示词用于正常整段、整段重试、拆分片段和附属文本请求；正常调用不增加额外提示段落。

### 强化公式提示词

整段重试和拆分片段调用均在基础 system prompt 后追加强化提示，要求：

- 完整处理输入中的所有英文内容；
- 包含占位符的句子也必须翻译占位符周围的英文；
- 占位符只能整体移动，内部不得插入空格、换行、标点或文字；
- 不得因术语、设备编号或公式而复制整句英文；
- 只返回完整译文或调用方要求的结构化结果。

### 拆分触发和分组

正常流程保持：整段翻译 → 占位符校验 → 整段重试 → 仍失败后拆分。

拆分阶段继续以 `FORMULA_SPLIT_MAX_CHARS = 600` 和 `FORMULA_SPLIT_MAX_FORMULAS = 4` 作为片段上限，但不再把“超过上限”作为唯一拆分条件：

- 先用现有完整英文句子识别逻辑切分；
- 如果识别出至少两个完整句子，即使总长度和公式数未超过阈值，也强制生成至少两个片段；
- 仍按句子合并多个片段，避免对每句话单独发请求；
- 单句对象不硬切，保留明确的“无完整句子边界可拆分”失败原因；
- 每个片段只携带自己包含的公式占位符，并独立校验和恢复。

### 片段结果

- 片段成功：恢复公式后加入结果；
- 片段失败：加入该片段英文原文并记录片段编号；
- 至少一个片段成功：正文整体为 `success`，并记录部分片段回退；
- 所有片段失败：正文整体为 `failed`。

## 测试设计

在现有测试基础上增加或调整：

1. 正常无公式段落仍只调用一次。
2. 正常整段成功不触发拆分。
3. 多句、短于 600 字符且公式少于 4 个的正文在公式校验失败后仍能拆成至少两个片段。
4. 拆分片段收到基础提示词加强化公式提示词。
5. `Fig.`、`Eq.`、`e.g.`、`i.e.`、`No.`、`et al.` 不被错误拆句。
6. 片段公式占位符校验失败时只回退该片段。
7. 单句正文不被字符硬切。
8. page 7 类似的 6 公式段落仍按公式上限分组，并验证失败片段不会导致成功片段丢失。
9. OpenAI-compatible client 验证基础 system prompt 和追加 instruction 的拼接结果。

## 预期收益和限制

该改动只会增加已发生公式校验失败正文的后续请求，不影响正常正文请求次数。它可以直接改善日志中存在多个完整句子的失败对象，并降低 page 7 类似结果中单个片段回退英文的概率。只有一个完整句子且模型始终破坏占位符的对象仍可能失败，因为设计不允许通过硬切字符破坏句子边界。
