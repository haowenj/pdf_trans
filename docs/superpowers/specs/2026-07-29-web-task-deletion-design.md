# Web 任务硬删除设计

## 背景

Web 首页会列出数据库中的解析任务，并允许用户查看日志、继续失败或中断的任务，以及打开成功任务的解析结果。目前列表没有删除入口，已经结束的任务会长期保留数据库记录、日志、原始 PDF 和全部解析产物。

CLI 任务不写入 Web 数据库，其目录名称以 `cli-` 开头，主要用于快捷测试。本功能只处理 Web 数据库中的任务及其 `data/tasks/<task_id>` 目录，不扫描、不判断也不删除任何 CLI 任务目录。按日期清理 CLI 目录将作为独立功能另行设计。

## 目标

- 允许用户从 Web 任务列表永久删除已经结束的任务。
- 删除数据库任务记录、关联日志、原始 PDF 和全部解析或翻译产物。
- 防止删除排队中或运行中的任务。
- 在文件清理失败时保留数据库信息，方便用户重试删除或排查问题。
- 为破坏性操作提供明确的二次确认和进行中反馈。

## 非目标

- 不删除或管理 `cli-*` 目录。
- 不提供按日期、批量或自动清理功能。
- 不实现软删除、回收站或恢复功能。
- 不增加数据库字段或 Alembic 迁移。
- 不允许删除 `queued` 或 `running` 状态的任务。

## 删除规则

允许删除的状态为：

- `succeeded`
- `failed`
- `interrupted`

不可删除的状态为：

- `queued`
- `running`

后端必须执行最终状态校验，不能只依赖前端隐藏按钮。不存在的任务返回 `404 Not Found`；状态不允许删除时返回 `409 Conflict`；成功删除返回 `204 No Content`。

## 后端设计

### API

在现有任务路由中新增：

```http
DELETE /tasks/{task_id}
```

路由从应用设置中取得 `data_dir`，并委托 Repository 完成状态校验、数据库删除与文件清理的事务协调。

### Repository 与事务

Repository 新增任务删除操作，接收任务 ID 和一个文件清理回调。删除过程为：

1. 开启数据库事务并锁定目标任务。
2. 任务不存在时抛出 `TaskNotFound`。
3. 任务状态不属于允许集合时抛出 `InvalidTaskState`。
4. 显式删除该任务的 `task_logs`，避免依赖不同数据库对外键级联删除的配置差异。
5. 删除任务记录并刷新数据库操作，但暂不提交事务。
6. 调用文件清理回调。
7. 文件清理成功后提交事务。

文件清理回调抛出异常时，数据库事务回滚，任务记录和日志继续保留。数据库最终提交失败时异常向上传递，不返回删除成功。

### 存储清理

存储模块新增一个只清理 Web 任务目录的函数。它根据已从数据库查到的任务 ID 构造：

```text
<data_dir>/tasks/<task_id>
```

函数必须验证目标是 `tasks` 根目录的直接子目录，拒绝绝对路径、父目录跳转或任何越界目标。目录存在时递归删除；目录已经不存在时视为清理完成，以便移除孤立数据库记录。

该函数不会枚举 `data_dir`，因此不会接触同级或其他位置的 `cli-*` 目录。

## 前端设计

### 按钮展示

服务端首次渲染模板和 `dashboard.js` 的 SSE 动态渲染都使用相同规则：

- `succeeded`、`failed`、`interrupted`：展示危险样式的“删除”按钮。
- `queued`、`running`：不展示删除按钮。

### 用户交互

1. 用户点击“删除”。
2. 浏览器确认框显示原始文件名，并明确提示将永久删除原始 PDF、日志和全部解析产物，且无法恢复。
3. 用户取消时不发起请求。
4. 用户确认后，按钮文字变为“删除中…”并禁用。
5. 前端发送 `DELETE /tasks/{task_id}`。
6. 成功后立即从 DOM 中移除该任务行；后续 SSE 快照中也不会再出现该任务。
7. 如果 Console 正在显示被删除任务，前端关闭日志连接并收起 Console。
8. 请求失败时保留任务行，恢复按钮状态，并在现有页面错误区域显示后端返回的错误信息或通用错误文案。

### 样式

在现有按钮体系中增加危险操作样式，保持桌面和窄屏布局可用。删除按钮不取代“继续”“查看”或 “Console”等现有动作。

## 并发与错误处理

- 后端状态校验是删除权限的唯一可信来源。
- 数据库事务在文件清理期间保持未提交，避免文件删除失败后列表记录已经消失。
- 任务锁和事务中的二次状态校验避免删除请求与“继续”请求同时修改同一任务。
- 文件系统权限、占用或其他 I/O 错误返回服务端错误，页面保留任务并允许重试。
- 已缺失的任务目录不阻止数据库清理。
- 删除成功后，对该任务的查看、下载、日志和继续接口均返回 `404`。

## 测试设计

### Repository 测试

- `succeeded`、`failed`、`interrupted` 任务可以删除。
- `queued`、`running` 任务抛出 `InvalidTaskState`。
- 不存在的任务抛出 `TaskNotFound`。
- 删除任务时显式删除全部关联日志。
- 文件清理回调失败时任务和日志均因事务回滚而保留。

### 存储测试

- 删除准确的 `data/tasks/<task_id>` 目录及其全部内容。
- 任务目录不存在时正常完成。
- 越界任务 ID 被拒绝。
- 同一数据根目录中的 `cli-*` 目录保持不变。

### 路由测试

- 允许状态返回 `204`，数据库记录、日志和任务目录全部消失。
- 不允许状态返回 `409`，任务目录和数据库内容保持不变。
- 不存在的任务返回 `404`。
- 文件清理失败返回 `500`，任务和日志仍可查询。

### 页面测试

- 服务端渲染仅为终态任务输出删除按钮。
- 动态渲染脚本仅为终态任务创建删除按钮。
- 脚本包含确认提示、请求进行中状态、错误恢复、成功移除任务行和关闭活动 Console 的逻辑。
- 危险按钮样式和现有响应式布局兼容。

### 完整验证

实现完成后运行完整 `pytest` 测试套件，确认新增删除功能和现有上传、执行、恢复、日志与文件查看功能共同通过。
