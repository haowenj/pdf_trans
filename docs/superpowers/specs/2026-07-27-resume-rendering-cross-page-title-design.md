# 断点翻译渲染与跨页标题保护设计

## 目标

修正两项既有行为：命令行 `--translate-only` 在断点翻译成功后生成
`rendered.md`；跨页候选检测不再把带 `text_level` 的标题文本纳入候选或合并。

## 范围

### 命令行断点翻译

`python -m pdf_trans --translate-only <normalized_content_list.json>` 保持现有的
翻译输入和输出约定：翻译结果仍写入同目录的
`translated_content_list.json`。翻译成功返回后，命令行使用现有
`render_content_list_file` 将该文件渲染为同目录的 `rendered.md`。

目标 Markdown 始终覆盖，以确保它与本次翻译后的 JSON 一致。命令行摘要新增
`Markdown 文件：<绝对路径>`。如果翻译或渲染失败，命令返回非零；渲染失败时不把
流程报告为成功。

该改动只位于命令行入口。`process_translation_file` 继续只负责校验和翻译，Web
任务执行器继续在其断点续传路径中单独渲染，避免改变公共工作流函数的职责或发生重复
渲染。

### 跨页候选检测

检测器遍历相邻对象时，只要前项或后项存在 `text_level` 键，就直接跳过该对。该规则
不依赖 `text_level` 的值或类型：字段存在即代表标题对象，避免正文与标题、标题与正文
或标题与标题被跨页合并。

其余候选条件保持不变：两项必须为相邻的非空 `text`，页码必须连续，且前项不得以
配置的英文句末标点结束。

## 测试

- CLI 测试验证 `--translate-only` 先完成翻译，再以返回的翻译文件作为渲染输入，输出
  与规范化文件同目录的 `rendered.md`，并在标准输出显示该路径。
- 跨页检测测试分别覆盖前项带 `text_level` 和后项带 `text_level`，两种情况都不得产生
  候选。
- 保留现有普通正文跨页候选测试，证明过滤标题不会改变正文合并行为。

## 非目标

- 不改变 Web 断点续传的渲染流程；它已经生成 `rendered.md`。
- 不扩展句末标点集合或改变候选报告格式。
- 不修改标题的翻译或 Markdown 标题渲染规则。
