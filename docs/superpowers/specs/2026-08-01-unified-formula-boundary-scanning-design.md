# 统一公式边界扫描设计

## 背景

项目当前存在三套公式扫描实现：`formula_scanner.py` 与 `web/markdown.py` 支持 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`，而 `formula_protection.py` 与 `table_cell_protection.py` 只支持美元符号边界。这使反斜杠边界公式在正文或表格单元格翻译时没有被替换成占位符，模型可以直接修改公式，后续恢复校验也无法发现。

根因是不同处理阶段各自维护私有公式扫描逻辑，边界集合和细节行为会独立演进。

## 目标与范围

- 正文翻译保护、表格单元格翻译保护、公式审计与替换、Web Markdown 渲染统一支持四种公式边界。
- 使用同一个公开扫描入口，统一转义、闭合判断、边界优先级和跨度计算。
- 保持现有占位符格式、哈希校验和恢复规则不变。
- 恢复后的公式必须与原文逐字符一致。
- 模型删除、增加、重复、篡改或调整公式占位符顺序时继续失败。
- 转义边界和未闭合边界继续作为普通文本处理。
- 不处理普通金额 `$5`、`$10` 可能被识别为公式的问题，也不修改其他业务逻辑。

## 统一扫描接口

`pdf_trans.formula_scanner` 公开以下接口：

```python
@dataclass(frozen=True)
class FormulaSpan:
    raw_formula: str
    katex_formula: str
    is_block: bool
    start: int
    end: int
    katex_start: int
    katex_end: int


def scan_formula_spans(source: str) -> tuple[FormulaSpan, ...]: ...
```

扫描顺序为 `$$...$$`、`\[...\]`、`\(...\)`、`$...$`，避免单美元符号抢占双美元符号。边界前连续反斜杠数量为奇数时视为转义；只有找到同类型、未转义的闭合边界时才返回跨度。扫描到完整公式后从公式末尾继续，保证结果不重叠并保持原文顺序。

`FormulaSpan` 沿用现有扫描器已经计算的完整原文、KaTeX 内容、块级属性及绝对位置，因此审计、替换、保护和 Markdown 渲染都不需要重新解释边界。

## 调用方改造

- `formula_scanner.py` 内部的正文扫描、表格 HTML 文本节点扫描及公式替换改用公开的 `scan_formula_spans()`。
- `formula_protection.py` 删除私有 `_is_escaped`、`_find_closing` 和 `_formula_spans`，保护与恢复校验通过统一 span 的 `start`、`end` 提取公式。
- `table_cell_protection.py` 同样删除私有扫描逻辑，通过统一 span 生成单元格公式标记并校验恢复结果。
- `web/markdown.py` 删除私有边界表和扫描函数，通过统一 span 生成 Markdown 安全占位符；现有 HTML 转义、占位符数量与顺序检查保持不变。

不改变正文或表格的占位符协议。统一扫描只替换“哪些内容被认定为完整公式”这一数据来源。

## 恢复与错误处理

正文保护继续验证随机 nonce、公式 ID、SHA-256 摘要、占位符原文、数量、重复、新增、缺失和顺序。恢复前拒绝模型新增的完整公式，恢复后用统一扫描器逐项比较公式原文。

表格单元格保护继续验证 `⟦M<n>⟧` 的数量、重复、新增、缺失、篡改与顺序，恢复时校验每条本地 SHA-256 摘要，并在恢复后用统一扫描器逐项比较公式原文。HTML 结构标记行为不变。

转义或未闭合边界不会产生 span，因此不会生成占位符，也不会进入恢复公式清单。

## 测试

先添加失败测试，再实施统一扫描：

- 统一扫描入口返回四种完整公式，保留原文、内容范围、块级属性和位置。
- 正文中的四种公式边界都被替换为占位符，并能逐字符恢复。
- HTML 表格单元格文本中的四种公式边界都被替换为单元格公式标记，并能逐字符恢复。
- 对包含 `\(...\)`、`\[...\]` 的正文与表格保护结果，缺失、篡改或调整占位符顺序均被拒绝。
- 四种边界的转义形式和未闭合形式均按普通文本处理。
- 既有 `$...$`、`$$...$$`、Markdown 安全渲染、正文恢复和表格分段测试继续通过。

验证顺序为相关单元测试、完整测试套件和项目既有静态检查；不修改与本问题无关的测试或实现。
