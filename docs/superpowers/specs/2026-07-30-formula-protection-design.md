# 翻译公式保护机制设计

## 目标与范围

在所有会进入翻译模型、且可能包含 LaTeX 公式的内容进入模型前，
将完整的行内公式 `$...$` 和块级公式 `$$...$$` 替换为稳定且唯一的占位符。
模型返回后必须先严格校验占位符，再按 ID 恢复原始公式。只有校验和恢复全部成功，
对应对象才允许写入 `translation_status=success`。

当前生产代码只有两类模型输入：

- `type=text` 对象的完整 `text`；
- `type=table` 对象中 `table_body` 解析出的 `caption`、`th` 和 `td`
  文本节点。

本次同时保护这两个入口。其他对象类型当前不会进入翻译模型，因此不改变其处理。
不处理 MinerU 对 `\neq`、`\neqq`、`\complement`、`\max` 等命令的识别错误，
也不修改前端公式渲染器。

## 根因

普通文本翻译目前直接把原始 `text` 发送给模型。表格翻译虽然只发送文本节点、
不会发送 HTML 标签，但文本节点中的公式仍以原始 LaTeX 形式进入模型。

普通文本返回后仅校验译文非空。表格返回后校验 JSON 形状、文本节点 ID 和 HTML
结构，但没有校验公式内容。因此模型可以把
`${15}^{\circ}\mathrm{C},\mathrm{kg}/\mathrm{m}^{3}$`
改成 `${15}^{\circ}\mathrm{C}}$`，同时绕过现有校验并被标记为成功。

## 公式识别

新增独立的公式保护模块。使用确定性扫描器从左到右识别公式：

- 在同一位置优先识别 `$$`，闭合边界也必须是 `$$`；
- 其余未转义的 `$` 作为行内公式边界；
- `\$` 不作为公式边界；
- 块级公式允许跨行；
- 未找到匹配闭合边界的 `$` 或 `$$` 保持普通文本，不臆测或修复 MinerU 内容。

公式记录包含完整边界，因此原始 `$...$` 或 `$$...$$` 会逐字恢复，包括所有空白、
换行、反斜杠、花括号和 LaTeX 命令。

## 占位符与保护上下文

每次模型请求创建一个公式保护上下文。同一次表格批量请求中的所有文本节点共享
该上下文，普通段落各自使用一个上下文。所有重试复用首次生成的上下文和占位符。

占位符使用不包含 LaTeX 特殊字符、且不易被自然语言模型翻译的哨兵格式：

```text
⟪PDFTRANS_FORMULA:<request_nonce>:<formula_id>:<sha256>⟫
```

- `request_nonce` 随请求随机生成，避免与原文内容碰撞；
- `formula_id` 是请求内单调递增、固定宽度的 ID；
- `sha256` 是包含 `$` 或 `$$` 边界在内的原始公式 SHA-256 摘要；
- 保护前如果普通文本已包含保留的 `PDFTRANS_FORMULA` 哨兵字样，则拒绝处理，
  避免把用户内容误认作内部占位符。

保护组件对外提供两个清晰职责：

1. `protect(text)` 返回不含原始公式的模型输入和该字段期望的占位符序列；
2. `restore(translated_text, protected_field)` 校验并恢复公式，失败时抛出专用异常。

模型看到的内容只包含普通文本和占位符，永远不包含被识别出的原始 LaTeX。

## 普通文本数据流

`_translate_one` 在进入重试循环前保护原始 `text`。每次尝试均向
`translator.translate()` 发送相同的受保护文本。

模型返回非空字符串后，先执行公式校验和恢复。恢复失败视为本次模型调用失败，
进入现有重试分支。只有恢复成功的完整译文才写入 `TranslationOutcome` 的成功结果。

没有公式的普通文本保持当前请求内容和行为，不额外修改文本。

## 表格数据流与 HTML 保护

现有 HTML 解析、文本节点提取、JSON Schema 响应格式和按偏移量回填机制继续保留。
保护逻辑只作用于每个 `TableTextNode.text`：

1. `prepare_table_translation()` 解析原始 HTML；
2. 所有可翻译节点共享一个公式保护上下文，各自生成受保护文本；
3. `build_request()` 只序列化节点 ID 和受保护文本；
4. `apply_response()` 仍先按 `table-text-*` ID 解析模型响应；
5. 每个节点分别校验并恢复其公式；
6. 恢复后的文本按现有逻辑进行 HTML 转义并回填原始 HTML；
7. 最后继续比较解析前后的 HTML 结构。

`<table>`、`<tr>`、`<td>`、`<th>`、`<caption>`、`rowspan`、`colspan`
及其他标签和属性不会进入模型，也不会由模型重建。公式恢复发生在 HTML 转义前，
反斜杠和花括号不受 HTML 转义影响。

表格翻译项仍允许按 `table-text-*` ID 改变返回顺序，这是既有合法协议。
但是公式绑定到原始文本节点：

- 公式移动到其他单元格会造成两个节点各自的 ID 集合不一致并失败；
- 同一节点中的多个公式顺序变化会失败；
- 不同节点在 JSON 响应数组中的排列变化不会被误判为公式顺序变化。

## 返回校验与恢复

每个受保护字段独立执行以下检查：

1. 返回文本中的完整占位符数量必须与该字段一致；
2. 占位符 ID 集合必须一致；
3. 不允许缺失、重复或新增 ID；
4. 占位符序列必须与发送前完全一致，不允许顺序变化；
5. nonce、ID 或摘要发生变化的哨兵必须被识别为篡改并拒绝；
6. 恢复前返回文本不得包含模型新生成的 `$...$` 或 `$$...$$` 公式；
7. 恢复时根据精确 ID 插入保存的原始公式，并重新计算其 SHA-256；
8. 恢复后重新提取公式，公式数量、顺序、逐字内容和摘要必须与翻译前一致；
9. 恢复后不得残留内部哨兵。

摘要用于检测记录或恢复过程中的内容不一致，不依赖模型返回摘要来替代本地原文。
最终公式始终来自本地保存的原始字符串，不从模型响应重建。

## 错误、重试与状态

公式识别、占位符校验和恢复错误使用明确的专用异常及中文错误信息，包括：

- 占位符数量不一致；
- 占位符 ID 缺失、重复或新增；
- 占位符被篡改；
- 占位符顺序变化；
- 模型新增公式；
- 恢复后公式内容或摘要不一致。

普通文本和表格的校验均位于现有每次模型调用的 `try` 块内。因此校验失败会记录
包含段落号或表格号、尝试次数及具体原因的 warning，并按当前
`max_retries + 1` 次数重试。重试耗尽后：

- 普通文本写入 `translated_text=null`、`translation_status=failed` 和
  `translation_error`；
- 表格不写入 `translated_table_body`，写入 `translation_status=failed`
  和 `translation_error`；
- 其他并发翻译任务继续执行。

任何公式校验失败的结果都不会经过成功 outcome，因此不能写入
`translation_status=success`。

已有断点文件继续沿用当前语义：已经标记为 `success` 的对象不会重新调用模型。
本次机制保证新产生的成功结果经过保护和校验，不对历史断点结果做迁移或追溯重验。

## 测试

公式保护单元测试覆盖：

- 单个及多个行内公式；
- 块级公式及跨行内容；
- 行内和块级公式混合；
- 转义美元符号与未闭合边界；
- 反斜杠、花括号、空白和 LaTeX 命令逐字恢复；
- 占位符缺失、重复、新增、篡改和顺序变化；
- 模型新增公式；
- 恢复后逐字内容和 SHA-256 一致。

普通文本集成测试覆盖：

- 发给模型的内容不包含原始 LaTeX；
- 单个和多个公式恢复后与原文逐字一致；
- 校验失败会重试；
- 重试耗尽后状态为 `failed`，错误日志和 `translation_error` 明确；
- 校验通过后才写入 `success`。

表格测试覆盖：

- 不同单元格中的公式使用唯一占位符并逐字恢复；
- 同一单元格中的多个公式；
- 块级公式；
- 公式所在单元格及普通单元格共同翻译；
- 节点 JSON 返回顺序可变化，但节点内公式顺序不可变化；
- 公式不能移动到其他单元格；
- `<table>`、`<tr>`、`<td>`、`rowspan`、`colspan` 和其他属性保持不变；
- 给定问题公式
  `${15}^{\circ}\mathrm{C},\mathrm{kg}/\mathrm{m}^{3}$`
  完整恢复；
- 表格公式校验失败沿用重试并最终标记 `failed`。

最后运行完整 pytest 测试集，确认现有翻译、表格结构、断点、并发、渲染和 Web
流程不受影响。
